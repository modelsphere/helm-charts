Adding or changing a route means editing that ConfigMap. Either way works, and
they do not conflict:

  - By hand:
      kubectl -n {{ .Release.Namespace }} edit cm {{ .Values.configMapName }}
    adding or removing session_route_<route>.conf entries.

  - With an operator: if you run the autoconfig operator, point a ModelRoute at
    this ConfigMap (openresty.outputConfigMap={{ .Values.configMapName }}) and it
    maintains those entries for you.

A helm upgrade will not clobber entries added by either route, as long as this
chart's template itself has not changed. A ConfigMap edit takes up to about a
minute to reach the pod, after which the reload sidecar picks it up.

Check the rendered configuration:
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "openresty.fullname" . }} -c openresty -- \
    /usr/local/openresty/bin/openresty -t
